## 1. Method and provenance

1. Segment axes come from the prompt overlay (age, region, institution
   relationship, data sensitivity) and BQ-03 - not from a single generic
   "student" persona.
2. Persona goals/frustrations are derived from spec problem statements
   (`01-vaeloom-mvp-spec.md` section 2, section 4, section 12), agent rosters
   (section 5), Gmail design (section 8), job-search constraints (section 9) and
   memory types (`04-memory-knowledge-graph.md` section 7.1).
3. Market context facts (unemployment, enrolment, ATS stats) are quoted only
   from the R-1 research brief with its own sources; they condition the
   personas' plausibility, they do not prove behavior.
4. Every claim maps to a spec section in the evidence status table (section 8);
   no row is fabricated, no row is left blank where the answer is unknown - it
   is marked `REQUIRES_STAKEHOLDER_DECISION` with an owner.

## 6. JTBD framework (functional / emotional / social)

Per-pair JTBD above are typed as: **F** functional (task completion), **E**
emotional (feeling state), **S** social (perception by others).

| Job type   | Definition                                                    | Examples from personas                                                                                                   |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Functional | The task the user hires the product to complete               | F1/F2/F3 in each persona: current resume, no missed deadlines, fit-before-apply                                          |
| Emotional  | The internal state the user wants to move away from or toward | E1: control and preparation (PA-01), reduced hidden-search anxiety (PA-02), confidence through rejection streaks (PA-03) |
| Social     | How the user wants to be seen by others                       | S1: professional image (PA-01), organized and intentional (PA-02), deliberate growth narrative (PA-03)                   |

## 7. Trust boundaries and unacceptable outcomes (prompt overlay)

| Unacceptable outcome | Definition                                                       | Guardrail in product design                                                                                                                        | Validated by |
| -------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| Wrong memory         | Assistant asserts a fact that is false or superseded             | Correction feedback loop (spec section 12.8); provenance-carrying projections over authoritative relational data; consolidation (spec section 7.4) | VB-02, VB-07 |
| Overreach            | Assistant acts in the world without explicit user approval       | Suggest-mode-first (spec section 3, section 12.1); payload-bound expiring approval + idempotency (INT-02); Gmail draft-only (spec section 8)       | VB-03        |
| Missed deadlines     | A deadline is extracted but not surfaced, or surfaced but missed | Gmail scheduled pass + push hook (spec section 8); Scheduler reminders + conflict detection (spec section 5)                                       | VB-01        |
| Confusing approvals  | User cannot tell what, why or when an action happens             | Proposed diffs with batch-approve (spec section 4.3); approval gates shown before anything leaves the system (spec section 4.7)                    | VB-03        |
| Difficult deletion   | User cannot export or erase data fully                           | "Export everything" and "delete everything" controls from day one (spec section 11); purge covers system of record + projections (INT-02)          | VB-05        |
