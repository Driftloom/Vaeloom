# Module 05: Architecture Overview & 10-Layer Cognitive Pipeline
**Audit Identifier**: `AUD-M05-AI-01`
**Scope**: End-to-end dataflow and component interaction topology.

---

## 1. The 10-Layer Cognitive Architecture

The Vaeloom document and workspace subsystem operates across 10 strictly segregated layers:

```
[Layer 1: Frontend Client (Next.js 15 / SWR / api-client.ts)]
                         │  HTTPS (TLS 1.3) + Bearer JWT + CSRF Token
                         ▼
[Layer 2: API Gateway & Security Filter (FastAPI / TenantMiddleware / CORS / RateLimit)]
                         │  Zero-Trust Workspace Context Binding
                         ▼
[Layer 3: Storage & Ingestion Boundary (S3 / MinIO / FileSecurityService / EICAR Scan)]
                         │  Storage Key Partitioning (storage/{tenant}/{workspace}/{doc_id})
                         ▼
[Layer 4: Ingestion Engine & Worker Pool (Temporal Workflow: IngestDocumentWorkflow)]
                         │  Async Non-Blocking Processing
                         ▼
[Layer 5: Text Extraction & Parsing (PyMuPDF / python-docx / Tesseract OCR)]
                         │  Structured Text Stream + Page Offsets
                         ▼
[Layer 6: Chunking & Sanitization (Semantic Chunker / PromptInjectionMiddleware)]
                         │  Poisoned Chunk Quarantine -> Zero Vector Fallback
                         ▼
[Layer 7: Vector Indexing & Hybrid Search (PGVector / Qdrant / FallbackVectorStore / TsVector)]
                         │  Mandatory Tenant/Workspace Filter Isolation
                         ▼
[Layer 8: Context Assembly & RAG Reranking (Cross-Encoder / Substring Suppress / Budget Fit)]
                         │  Token Budget Enforced Prompt Assembly
                         ▼
[Layer 9: Agent Reasoning & LLM Routing (DocumentAgent / WorkspaceAgent / LLMService)]
                         │  Tool Call Scope Validation & Parameter Tampering Guard
                         ▼
[Layer 10: Memory, Sovereign Graph & Output (MemoryRecord / Sovereign KG / Citations)]
```

---

## 2. Key Design Invariants

1. **Fail-Closed Workspace Binding**: Every database interaction sets `app.workspace_id`, `app.tenant_id`, and `app.user_id` in PostgreSQL session variables via `set_rls_session_vars`.
2. **Object Storage Isolation**: Documents are never stored in a flat S3 prefix. Storage keys strictly prefix `storage/{workspace_id}/{document_id}/{filename}` to ensure zero cross-workspace leaking at the bucket level.
3. **Quarantine Before Embedding**: Any document chunk flagged by `PromptInjectionMiddleware._scan()` is quarantined with a zero-vector (`[0.0] * 1536`), preventing embedding space poisoning.
4. **Verifiable Citations**: Every synthesis generated by `DocumentAgent.synthesize_documents()` includes deterministic `DocumentCitation` structures mapping to the exact source document ID, title, and excerpt.
