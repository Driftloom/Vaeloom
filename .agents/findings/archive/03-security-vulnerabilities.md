# Security Vulnerabilities — Backend Audit

**Audit scope:** Backend security posture after PR #29 merge **Method:** Read
csrf.py, tenant.py, config.py, dependencies.py, auth.py, middleware chain

## CRITICAL

### 1. Tenant Isolation Bypass via `X-Tenant-ID` Header

**File:** `apps/api/src/api/dependencies.py`

```python
async def get_current_tenant(request: Request) -> str:
    tenant_id = request.headers.get("X-Tenant-ID") or getattr(request.state, "tenant_id", None)
```

**The Problem:** `TenantMiddleware` (tenant.py) correctly validates the JWT
tenant and ignores header mismatches. But `get_current_tenant()` is a **separate
dependency** used by route handlers — it reads the header directly,
**bypassing** the middleware's trust logic.

**Attack:** An attacker can set `X-Tenant-ID` to any tenant UUID and access that
tenant's data if the route uses `get_current_tenant` instead of the
middleware-trusted value.

**Fix:** `get_current_tenant` must read `request.state.tenant_id` (set by
middleware) instead of re-reading the header.

---

### 2. CSRF Cookie Flags Insecure

**File:** `apps/api/src/api/main.py:162-163`

```python
response.set_cookie(
    "csrf_token", token,
    secure=False,    # ← Sent over plaintext HTTP
    httponly=False,  # ← JavaScript can read it
    samesite="lax",
)
```

**The Problem:**

- `secure=False` means the cookie is sent over plaintext HTTP — vulnerable to
  MITM sniffing
- `httponly=False` allows JavaScript to read the cookie — enables XSS-based CSRF
  token theft
- The double-submit pattern (header must match cookie) partially mitigates this,
  but an attacker who can inject JS can extract both values

**Fix:** Set `secure=True` and `httponly=True` in non-local environments.

---

### 3. CSRF Token Store is In-Memory Singleton

**File:** `apps/api/src/api/middleware/csrf.py:49`

```python
_token_store = CSRFTokenStore()  # In-process dict
```

**The Problem:** With multiple workers/processes, each worker has its own store.
A token generated by worker A will fail validation on worker B. This causes 403
errors under concurrency.

**Not a vulnerability** in single-worker mode but will break in production with
multiple workers.

**Fix:** Use Redis-backed token store (the rate limiter already has Redis
integration).

## HIGH

### 4. CORS Allows localhost in Production

**File:** `apps/api/src/api/config.py:142-145`

```python
if "localhost" in settings.allowed_origins and settings.environment != "local":
    logger.warning("localhost in allowed_origins in non-local environment")
```

**The Problem:** This is only a warning, not an error. An operator can deploy to
production with `localhost` origins and the app starts successfully.

**Fix:** Make this an error in non-local environments.

---

### 5. Auth Endpoints Bypass Both Auth and CSRF

**File:** `apps/api/src/api/middleware/csrf.py:15`

```python
SKIP_PREFIXES = frozenset({"/api/v1/auth"})
```

**File:** `apps/api/src/api/middleware/auth.py:18-20`

```python
PUBLIC_PATHS = {"/csrf-token", "/api/v1/auth/signup", "/api/v1/auth/login", "/api/v1/auth/refresh"}
```

**The Problem:** POST to `/api/v1/auth/login` is unprotected by both auth and
CSRF. This is expected for login but means a CSRF attack can force a login to an
attacker-controlled account if the frontend uses the response.

**Severity:** HIGH (depends on frontend session handling)

---

### 6. IP Allowlist Not Mounted

**File:** `apps/api/src/api/main.py:139-140`

The `IPFilterMiddleware` is only mounted when `settings.ip_allowlist` is set. If
not configured, no IP filtering is applied.

**Severity:** HIGH (configuration-dependent)

## MEDIUM

### 7. Modal Missing `inert` on Background Content

**File:** `packages/ui-kit/src/components/Modal.tsx`

Background elements are not marked with `inert` or `aria-hidden="true"`. Screen
readers can still access background content through virtual buffer.

## LOW / Correctly Implemented

### 10. CSRF Double-Submit Pattern — Correct

Token is HMAC-signed with `jwt_secret`, cookie and header must match, tokens
have 1-hour TTL with eviction. The pattern is correct.

### 11. Tenant Isolation via RLS — Correct

`SET LOCAL` is transaction-scoped, safe with PgBouncer. Fail-closed (unset GUCs
= zero rows).

### 12. JWT Validation — Correct

Uses `settings.jwt_secret`, handles expired/invalid tokens.

### 13. Secret Handling at Startup — Correct

`validate_settings()` refuses to start with empty `jwt_secret` or short
`encryption_key`.
