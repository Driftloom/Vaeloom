### FINDING-001: RLS Policies Reference Non-Existent Columns (15 tables)

**Severity:** CRITICAL · **Status:** FIXED by migration 0012

Migration 0005 creates RLS policies with this USING clause:

```sql
USING (workspace_id = current_setting('app.workspace_id', true)::uuid
       AND tenant_id = current_setting('app.tenant_id', true)::uuid)
```

PostgreSQL will **error on policy creation** if the referenced column doesn't
exist. These tables are in `SCOPED_TABLES` but are **missing one or both
required columns**:

| --------------------- | ------------------------------------------------ | -------------- | ---------------------------------- |
| `notifications`       | `tenant_id`                                      | :704           | Column does not exist              |

| `embeddings`          | `tenant_id`                                      | :333           | Column does not exist              |
| `agents`              | `tenant_id`                                      | :419           | Column exists (nullable) ✓         |
| `agent_executions`    | `tenant_id`, `user_id` are `String(36)` not UUID | :449-450       | Type mismatch with `::uuid` cast   |
| `agent_actions`       | `tenant_id`                                      | :468           | Column does not exist              |
| `auth_sessions`       | `tenant_id`                                      | :60            | Column does not exist              |
| `usage_records`       | `tenant_id`                                      | :691           | Column exists (nullable) ✓         |
| `subscriptions`       | `tenant_id`                                      | :641           | Column exists (nullable, unique) ✓ |
| `webhook_deliveries`  | `tenant_id`                                      | :674           | Column does not exist              |

| `plugin_executions`   | `tenant_id`                                      | :777           | Column does not exist              |

| `idempotency_records` | `workspace_id`, `tenant_id`                      | :494           | Neither column exists              |

**Fix applied:** Migration 0012 (`0012_fix_rls_policies.py`) drops all broken
policies and re-creates them only for tables with correct column types.

## INFO

### FINDING-014: RLS Dual-Key Design Limits Coverage

**Severity:** INFO · **Status:** ACCEPTED

The dual-key policy (tenant_id + workspace_id) requires both columns to exist.
Tables missing one column cannot have working RLS. A single-key policy
(tenant_id only) would be simpler but weaker.
